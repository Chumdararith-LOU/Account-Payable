| D-053 | Extraction derives tax when the VAT label is garbled but the amount is read | 2026-09-28 | Extends D-044. | D-058 | The P1-12c "400 vs 422" anomaly was a test-harness bug, not a platform or framework issue | 2026-09-30 | The D.7 check built the X-API-Key header by grepping APMATCH_API_KEY out of .env and taking the value field. Because .env also holds a comment line that mentions APMATCH_API_KEY, the unanchored grep matched two lines and injected an embedded newline into the header value. A header containing a newline is malformed HTTP, so uvicorn's h11 parser rejected the request with 400 "Invalid HTTP request received" before it ever reached FastAPI. With a correctly extracted single-line key (anchored match on the KEY= line), the identical missing-field requests return FastAPI's documented 422 ({"detail":[{"type":"missing","loc":["body","invoice"],"msg":"Field required"}]}). No QEMU involvement, no uvicorn bug, no app change required. Lesson: extract env values with an anchored match, not a bare substring grep. |

| D-074 | OCR-noise regex extended to mixed-case suffixes | 2026-10-11 | The original /[a-z]{1,8}\b pattern (D-018) stripped only all-lowercase noise. Extended to /(?:[a-z]{1,8}|[A-Z][a-zA-Z]{1,7})\b — two alternatives: all-lowercase runs (1-8 chars, existing) and uppercase-starting runs (2-8 chars, new). Preserves single-uppercase patterns like P/N 12345, digit suffixes (1/2 inch), and runs that continue into digits (Part/AB123 — no word boundary between letter and digit). Note: the second alternative uses [a-zA-Z] (not [a-z]) after the leading uppercase so that mixed-case noise like /HiU is also stripped; this was validated against the fixture corpus via scripts/diagnose_match_failure.py, where the /match result went from DISCREPANCY (score 0.8, NO_MATCHING_PO_LINE) to MATCH (score 1.0).
