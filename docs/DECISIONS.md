| D-011 | Frozen dataclasses in apmatch/schema/, Decimal-only money, float rejection | 2026-09-27 | Prevents silent monetary drift; schema is the contract every downstream module consumes. |
| D-012 | ValidationResult uses enum codes + severity, not message strings | 2026-09-27 | Keeps remarks, matching, and audit log decoupled from each other. New failure modes are added by extending CheckCode, never by string-matching messages. |
| D-013 | tax_rate/discount_rate optional; two-mode tax/discount checks | 2026-09-27 | When a rate is provided, TAX_MISMATCH is a real arithmetic check (BLOCKER). When absent, it degrades to a sanity check (WARNING) with an explicit "sanity-only" location tag so audit logs are unambiguous. |
| D-014 | Drop created_at from document dataclasses | 2026-09-27 | DB metadata, not document content. Keeps validation results reproducible across runs. |
| D-015 | Template-based remarks, no LLM | 2026-09-27 | Replaces the deleted remark_generator.py (D-005). Every CheckCode maps to exactly one template string. Import-time assertion fails loudly if a code lacks a template; silent fallbacks are forbidden. Determinism and no-LLM-in-path are both regression-tested. |
| D-016 | summarize() contract: "N issue(s). Most severe: ..." for multi-failure results | 2026-09-27 | The result's checks_failed tuple is already ordered by severity (P1-06 contract), so summarize() can trust the first element. Removes ambiguity for reviewers reading logs. |
| D-017 | Tolerances are Python constants, not config files | 2026-09-27 | Determinism and reviewability; config files invite per-install drift and hidden state. |
| D-018 | normalize_text strips only low-risk OCR noise | 2026-09-27 | The /[a-z]{1,8}\b regex targets observed noise (e.g. "/nnw") while preserving legitimate slashes followed by uppercase, digits, or long runs. Errs toward keeping content. |
| D-019 | Legacy ai_engine.py is not ported directly; its normalize_text and tolerances are re-derived here | 2026-09-27 | P1-08b builds on these primitives; the legacy file will be replaced (not refactored in place) when the new engine lands. |
| D-020 | MatchResult uses enum MatchCode + Severity, never free text | 2026-09-27 | Mirrors D-012 for validation. Downstream (remarks, routing, audit) switches on MatchCode; failures are ordered (severity desc, code asc, location asc) so the order is part of the contract. |
| D-021 | Score = 1.0 minus sum of MATCH_CODE_WEIGHTS, clamped [0,1]; missing doc → PENDING_INFO/0.0 short-circuit | 2026-09-27 | Bounded, deterministic, Decimal-weighted. A missing PO/GRNI/PARD short-circuits before any other check so a partial match is never scored as if complete. |
| D-022 | PO currency check reads via getattr and skips when absent | 2026-09-27 | PurchaseOrder (P1-06) has no currency field (schema gap). getattr keeps the check forward-compatible and guarantees no false positive until the field exists. |
| D-023 | Line join on normalize_text(description), first source-order match; qty exact, price/amount abs-OR-rel | 2026-09-27 | Deterministic join key; exact qty catches real over/under-billing, while the relative tolerance (P1-08a) keeps large-value lines from tripping on a cent. |
| D-024 | Add optional currency to PO and PARD; skip currency check when either side absent | 2026-09-27 | P1-08b left CURRENCY_MISMATCH dormant (no schema field to compare against). Adding the field with default None is non-breaking. GRNI deliberately excluded — no monetary values. Supersedes the getattr workaround in D-022. |
| D-025 | Match remarks use the same template discipline as validation remarks | 2026-09-27 | Parallel module apmatch/remarks/matching.py. No LLM, no fallback. summarize_match follows the same shape contract as summarize (P1-07 D-016). |
| D-026 | First end-to-end deterministic pipeline test lives in tests/integration/ | 2026-09-27 | Proves dataclass → validation → matching → remark runs with zero ML and zero network. Fixtures under tests/integration/fixtures/ are the seed of the P1-13 corpus. |
| D-027 | Routing is three-valued: AUTO_APPROVE, HUMAN_REVIEW, REJECT | 2026-09-27 | AUTO_APPROVE requires a clean ValidationResult, MatchResult.outcome == MATCH, and OCR confidence above threshold (when provided). REJECT fires only on a validation BLOCKER. Everything else is HUMAN_REVIEW. The route is the system's only exit decision. |
| D-028 | Score combines validation + matching (+ OCR) with renormalized weights when OCR confidence is absent | 2026-09-27 | Prevent a missing OCR signal from artificially depressing the score. Weights are Python constants (D-017 discipline continues). |
| D-029 | Confidence scoring and routing have their own no-LLM AST test | 2026-09-27 | The route is the final exit decision; proving it contains no generative path is a precondition for the bank pitch. |
| D-030 | Postgres 16 + SQLAlchemy 2.x + Alembic for persistence | 2026-09-27 | NUMERIC(18,4) for all money; Float is forbidden by schema test. SQLite prototype used REAL (float) which silently drifts on large totals. Cutover is not backward-compatible; the legacy DB is dev-only data. |
| D-031 | docker-compose provides the local dev Postgres | 2026-09-27 | Dev credentials in docker-compose.yml are local-only; production uses env-var URL injection (P1-12). Port 5433 (not 5432) to avoid clashing with any system Postgres. |
| D-032 | Repository API is dataclass-in / dataclass-out; ORM instances never cross the boundary | 2026-09-27 | Keeps business logic independent of SQLAlchemy and makes round-trip tests trivial. |
| D-033 | UPSERT is delete-then-insert for lines, update-or-replace for headers | 2026-09-27 | Simpler to reason about than merge(); avoids SQLAlchemy identity-map surprises and produces predictable line ordering. |
| D-034 | load() raises DocumentNotFound with kind + identifier | 2026-09-27 | A bare KeyError loses context; reviewers and audit logs need to know which document kind was missing and by what identifier. |
| D-035 | SQLite → Postgres migration is dev-only, one-shot, Decimal(str(value)) conversion | 2026-09-27 | The legacy DB is fixture data. Production uses Alembic migrations against an empty schema. The float→Decimal conversion at the boundary is explicitly documented because it's the only place float is touched. |
| D-036 | Migrator derives line.amount and header.subtotal / total when the legacy schema stores only inputs | 2026-09-27 | The P1-06 schema requires explicit outputs; the legacy SQLite schema stored only quantity and unit_price. Derivation uses the same MONEY_QUANTUM and ROUND_HALF_UP as the dataclass layer. Without this, migrated fixtures fail our own validator, making them useless for downstream smoke tests. |
| D-037 | Audit log has no FKs to documents; append-only by repository design | 2026-09-28 | The audit record is independent evidence. A deleted document must not erase the decision that referenced it. update/delete/upsert methods are absent — no mutable operations exist at the API level. |
| D-038 | input_hash is SHA-256 over canonical JSON of the four documents | 2026-09-28 | Tamper-evidence. Same inputs → same hash, byte-for-byte, across processes. Enables third-party verification of a stored decision. |
| D-039 | Audit failure tuples are stored structurally (JSONB), not as rendered strings | 2026-09-28 | Preserves downstream queryability; a future dashboard can filter by CheckCode or MatchCode without parsing text. |
| D-040 | KPI functions return frozen dataclasses, not generators | 2026-09-28 | Bounded in memory; forces aggregates to run in Postgres, not Python. Prevents an N+1 pattern where a caller iterates over 100k rows to compute a count. |
| D-041 | top_discrepancy_invoices orders by score_value ASC, then run_timestamp DESC | 2026-09-28 | Reviewer attention is scarce; lowest-confidence runs are the most likely to be wrong. Recency is the tiebreak. |
| D-042 | Extraction layer is total (never raises for missing fields) | 2026-09-28 | The validator (P1-06) is the sole authority on what counts as a blocker. If the extractor raised, the validator would never see the half-populated document and couldn't report which fields were missing. |
| D-043 | Date parsing tries ambiguous formats in a fixed order; DD/MM wins over MM/DD | 2026-09-28 | The AP corpus in Cambodia and the region is DD/MM; the legacy DB used %d-%b-%Y (unambiguous). Documented and tested. |
| D-044 | Extraction derives implicit totals when absent | 2026-09-28 | Same policy as P1-10c-fix. Preserves explicit source values; derives line amounts, subtotal, total when the source omits them. |
| D-048 | Ruff for linting; RUF032 enabled deliberately | 2026-09-28 | The single most important rule for us: Decimal-from-float is banned in production code. Test code uses Decimal("...") string construction. Line length is a formatter concern (ruff format), not a linter concern (ruff check). Formatting is not run in this task. |
| D-049 | UP042 (StrEnum migration) deferred to a dedicated task | 2026-09-28 | Switching `class X(str, Enum)` to `StrEnum` changes `str(member)` output from `"X.MEMBER"` to `"MEMBER"`. Our code uses `.value` today, but audit logs and remarks are string-sensitive; the migration will land with an explicit test asserting the new behavior, not as a lint cleanup. |
| D-050 | Legacy root files retain 6 E701 violations until P1-14 | 2026-09-28 | ai_engine.py and api.py are being deleted in P1-14. Fixing their style now is wasted effort. |
| D-051 | HTTP API is FastAPI; config is plain module vars, not pydantic-settings | 2026-09-28 | Five env vars don't justify a new dependency. `apmatch/api/config.py` reads the environment at import and fails fast (no default API key). `/match` is a sync `def` so FastAPI runs the blocking OCR pipeline in its threadpool instead of stalling the event loop. Auth is an `X-API-Key` header; errors are enum-coded (`ErrorResponse`) — no stack traces, no document content, no file names in responses or logs. |
| D-052 | API remark rule: MATCH → validation summary, non-MATCH → match summary | 2026-09-28 | For a clean match the reviewer needs the validation state (the match is uninteresting); for a discrepancy the match summary explains it. The two remark modules (`templates.py`, `matching.py`) stay independent; the API picks which one to surface. |
| D-053 | Extraction derives tax when the VAT label is garbled but the amount is read | 2026-09-28 | Extends D-044. Live OCR misread the invoice's VAT *label* as Khmer while reading the amount correctly, so `tax_amount` came back None and `validate_invoice` crashed (it assumed well-formed money). Since `total = subtotal - discount + tax` and the invoice parser does not extract discount, `tax = total - subtotal` recovers the real value and keeps the schema's non-Optional money contract intact. The saved `output/ocr/*.json` fixtures carry a clean VAT label, which is why the parse tests never caught this. |
| D-054 | Validators never raise for missing data; they emit MISSING_REQUIRED_FIELD and skip dependent checks | 2026-09-28 | Enforces the P1-06 (D-012) contract end-to-end. P1-12d exposed a crash path (`Decimal + NoneType`) when the parser returned None for a nominally-required money field. The parser-level tax-derivation patch (D-053) fixed the specific case but not the contract; this decision fixes the contract. Each validator now runs in three passes: (1) required header fields, (2) required line fields, (3) arithmetic checks guarded by the presence of their inputs. One MISSING_REQUIRED_FIELD per missing field; optional fields (e.g. PO line `amount`) are skipped with no failure. |
| D-055 | Models are baked into the container image | 2026-09-29 | Bank install: pull one artifact, run it. Model updates ship as image versions, not as out-of-band file drops. Image size ~2–3 GB accepted as the cost of a self-contained install. A volume mount at `/app/models` overrides the baked-in copy for dev iteration. |
| D-056 | API key is required at compose start (`${VAR:?}`) | 2026-09-29 | A container starting with no API key is a security hole. Fail fast at compose config time rather than accept the request and discover the missing key later. `docker compose config` refuses to resolve when `APMATCH_API_KEY` is unset. |
| D-057 | Uvicorn runs single-worker | 2026-09-29 | Model load cost is ~1.2 GB per worker. Horizontal scaling is via container replicas, not uvicorn workers. `--workers > 1` would multiply the model memory and slow startup with no throughput gain for this workload. |
| D-058 | The P1-12c "400 vs 422" anomaly was a test-harness bug, not a platform or framework issue | 2026-09-30 | The D.7 check built the X-API-Key header by grepping APMATCH_API_KEY out of .env and taking the value field. Because .env also holds a comment line that mentions APMATCH_API_KEY, the unanchored grep matched two lines and injected an embedded newline into the header value. A header containing a newline is malformed HTTP, so uvicorn's h11 parser rejected the request with 400 "Invalid HTTP request received" before it ever reached FastAPI. With a correctly extracted single-line key (anchored match on the KEY= line), the identical missing-field requests return FastAPI's documented 422 ({"detail":[{"type":"missing","loc":["body","invoice"],"msg":"Field required"}]}). No QEMU involvement, no uvicorn bug, no app change required. Lesson: extract env values with an anchored match, not a bare substring grep. |
| D-059 | Deployed Docker image is amd64-only | 2026-09-30 | paddlepaddle==3.3.1 has no linux/arm64 wheel (arm64 wheels stop at 3.2.2). The bank deployment target is amd64 servers. arm64 builds are not supported with the current Paddle stack. If a customer requires arm64, options are: (a) pin Paddle to 3.2.2 and re-validate all OCR tests, or (b) wait for upstream arm64 wheels. |
